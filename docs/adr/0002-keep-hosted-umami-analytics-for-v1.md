# Keep hosted Umami Analytics for v1.0, disclosed alongside the other external services

As part of deciding the v1.0 privacy/trust commitments ([issue #30](https://github.com/lbacik/paysubscriptions/issues/30)), we considered switching to self-hosted Umami (keeps analytics data off third-party infrastructure entirely) or dropping analytics altogether, against keeping the hosted service as-is. We decided to keep hosted Umami Cloud (loading on every page including the maintenance page): it's cookieless and doesn't collect personal data, so no consent banner is legally required, and self-hosting is an operational cost that doesn't fit the solo-maintainer constraint on this effort.

Correction ([package approval](https://github.com/lbacik/paysubscriptions/issues/28), [audit](https://github.com/lbacik/paysubscriptions/issues/47)): Umami Cloud is not the only external service, so the v1.0 privacy policy must not present it as the sole exception and must not make an unqualified no-third-party-sharing claim. The application also loads Google Fonts and Font Awesome from CDNs on every page, Google reCAPTCHA on the contact form, sends transactional mail through the configured mail provider, forwards newsletter opt-ins to the shared gprodb.com list via an AMQP exchange, and links to BuyMeACoffee on the pricing page (click-through only, no automatic request). The email-bearing Robohash avatar URL was removed in #47. The full inventory lives in [docs/third-party-services.md](../third-party-services.md) and is pinned by `tests/Privacy/ExternalServicesTest.php`.

The v1.0 privacy policy ([issue #49](https://github.com/lbacik/paysubscriptions/issues/49)) must instead state that account and Subscription data is not sold, name each inventoried service with the data it receives, and explain the newsletter as a separate opt-in with its own unsubscribe path.
