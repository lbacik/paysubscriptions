# Current PaySubscriptions product baseline

_Evidence snapshot: PaySubscriptions v0.4.2, commit [`0bc99f2`](https://github.com/lbacik/paysubscriptions/commit/0bc99f28c53a8361528cae839c83af44eab7b3f3), inspected 2026-09-03. “Operational” below means observed on the deployed site; “source-implemented” means present in the released code but not proven end to end in this review._

## Baseline in one paragraph

PaySubscriptions is currently a free, single-account, manual subscription-expense tracker. A signed-in user can record a subscription name, first-payment date, and either a monthly or yearly amount; the dashboard is designed to list, sort, add, edit, and delete those records, calculate monthly and yearly equivalents and totals, and visualize spending in calendar-month, monthly, and yearly charts. Accounts are intended to use email/password registration with email verification, remember-me login, and password reset, with a default limit of 30 subscriptions. Public home, About, pricing, and sign-in pages are live, but registration, contact, and password-reset entry pages currently return HTTP 500. The product does **not** currently model currency, payment method, renewal state, a next due date, reminders, or customizable notifications.

## Copy-ready short description

> PaySubscriptions is a free, manual subscription expense tracker. Record each subscription’s name, first payment date, and monthly or yearly cost, then use one dashboard to compare normalized monthly and yearly totals and see how recurring spending is distributed across the year.

This is accurate for the implemented core. Until the live onboarding failures are resolved and the authenticated flow is covered by tests, public copy should avoid implying that a new visitor can reliably sign up and use it.

## v1.0 readiness constraints

### Release blockers

1. **New-user and support flows fail in production.** On 2026-09-03, direct GET requests returned HTTP 500 for [registration](https://paysubscriptions.com/register), [contact](https://paysubscriptions.com/contact), and [password reset](https://paysubscriptions.com/reset-password). Home, About, pricing, and sign-in returned 200, while Dashboard returned the expected 302 to sign-in. This prevents a new visitor from becoming a user, prevents a locked-out user from recovering, and removes the advertised support channel. The cause cannot be established without production logs; the observation should become explicit defect work.
2. **Edit and delete lack object-level ownership authorization.** `SubscriptionController` protects routes only with `ROLE_USER`, then resolves any `Subscription` by route id and updates or removes it without checking `subscription.owner === current user`; no voter or owner-scoped repository lookup is present. UUIDs reduce casual discovery but do not provide authorization. This is a cross-account modification risk and a v1.0 security blocker. [Controller evidence](https://github.com/lbacik/paysubscriptions/blob/0bc99f28c53a8361528cae839c83af44eab7b3f3/src/Controller/SubscriptionController.php#L17-L113); [repository evidence](https://github.com/lbacik/paysubscriptions/blob/0bc99f28c53a8361528cae839c83af44eab7b3f3/src/Repository/SubscriptionRepository.php#L15-L28).
3. **There is no behavioral test coverage.** `tests/` contains only `bootstrap.php`; PHPUnit reports “No tests executed!” The gate verifies container compilation, syntax, migrations, and fixture loading, but not registration, authentication, ownership isolation, subscription CRUD, limits, calculations, charts, contact, or newsletter behavior. The workflow itself records this limitation. [Test workflow](https://github.com/lbacik/paysubscriptions/blob/0bc99f28c53a8361528cae839c83af44eab7b3f3/.github/workflows/test.yml#L101-L140).
4. **Legal/privacy consent is not backed by accessible terms or privacy information.** Registration requires an “agreeTerms” checkbox, but the UI provides no terms link, and the released route set has no terms, privacy, or account/data-deletion page. The service collects account email and subscription-spending data, loads third-party fonts/icons/analytics on every page, and offers newsletter transfer to gprodb.com. This needs an explicit policy and consent/data-lifecycle decision before a “trustworthy public product” release. [Registration form](https://github.com/lbacik/paysubscriptions/blob/0bc99f28c53a8361528cae839c83af44eab7b3f3/src/Form/RegistrationFormType.php#L19-L58), [registration template](https://github.com/lbacik/paysubscriptions/blob/0bc99f28c53a8361528cae839c83af44eab7b3f3/templates/registration/register.html.twig#L11-L26), and [global third-party resources](https://github.com/lbacik/paysubscriptions/blob/0bc99f28c53a8361528cae839c83af44eab7b3f3/templates/base.html.twig#L1-L24).

### Product-integrity gaps

- **Currency semantics are absent.** Totals are only meaningful if every entered amount uses the same unstated currency. This must be made explicit or modeled before financial insights can be described as trustworthy.
- **“First payment” is overloaded as annual billing month.** It does not represent recurrence cadence or next charge. Past and future years have no behavioral meaning, although a full date is required.
- **The user cannot represent common lifecycle states.** There is no active/cancelled status, trial, renewal/cancellation date, category, notes, URL, or variable billing interval. Final v1.0 scope belongs to later Wayfinder tickets, but the current baseline should not be mistaken for complete subscription management.
- **Documentation is effectively empty.** The public About page contains a short marketing paragraph, while `Dashboard.md` is a headings-only stub and is excluded from the docs menu. [About source](https://github.com/lbacik/paysubscriptions/blob/0bc99f28c53a8361528cae839c83af44eab7b3f3/docs/About.md#L1-L31); [documentation menu logic](https://github.com/lbacik/paysubscriptions/blob/0bc99f28c53a8361528cae839c83af44eab7b3f3/src/Service/Documentation.php#L7-L54).
- **Basic accessibility/privacy polish is incomplete.** The base `<html>` element has no language, one homepage image has no alt text, the mobile-menu button’s `aria-controls` does not match the menu id, and every page loads third-party resources. These are examples, not a full audit. [Base template](https://github.com/lbacik/paysubscriptions/blob/0bc99f28c53a8361528cae839c83af44eab7b3f3/templates/base.html.twig#L1-L24); [homepage images](https://github.com/lbacik/paysubscriptions/blob/0bc99f28c53a8361528cae839c83af44eab7b3f3/templates/home/index.html.twig#L7-L10); [header menu](https://github.com/lbacik/paysubscriptions/blob/0bc99f28c53a8361528cae839c83af44eab7b3f3/templates/partials/_header.html.twig#L29-L45).

## Verification record and limits

- Live HTTP checks on 2026-09-03: `/`, `/about`, `/pricing`, and `/login` returned 200; `/dashboard` returned 302 to `/login`; `/register`, `/contact`, and `/reset-password` returned 500.
- On the v0.4.2 source: Composer manifest validation, Symfony container lint, all 28 YAML files, all 44 Twig files, and Doctrine mapping validation passed locally. Composer audit reported no advisories.
- PHPUnit completed successfully only because there are no tests. This is not behavioral evidence.
- The current GitHub [Test](https://github.com/lbacik/paysubscriptions/actions/runs/33742202869) and [Quality](https://github.com/lbacik/paysubscriptions/actions/runs/33742202877) runs passed, including migrations, fixture loading, mapping validation, Twig lint, and dependency audit.
- No production data was read and no production form was submitted. Authenticated dashboard behavior was therefore established from released source, not from a live user journey.

## Fact bank for later positioning and page work

Use these as the truthful building blocks:

- **Category:** manual subscription expense tracker.
- **Current user model:** one individual account; no sharing or organization.
- **Input promise:** name, first payment date, and either monthly or yearly amount.
- **Core benefit:** one list, normalized monthly/yearly equivalents and totals, and chart-based spending distribution.
- **Offer:** free, default maximum 30 subscription records, no paid upgrade path today.
- **Trustworthy boundaries:** no automatic discovery, bank connection, email scanning, provider integration, currency handling, cancellation service, next-renewal calculation, or reminder notifications.
- **Do not promise yet:** reliable self-service onboarding, household collaboration, business management, comprehensive reporting, currencies, deadlines/renewals, or notifications.
